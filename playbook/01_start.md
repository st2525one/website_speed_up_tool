# 01 着手から完了まで

## 最初に決めること

「遅い」を画面と操作に置き換える。「Wi-Fiがないと開かない」は原因ではなく利用状況である。場所、通信契約、端末、ブラウザー、発生URL、初回か再アクセスか、動画開始か表紙表示かを聞く。回線品質・DNS・TLS・サーバー障害もあり得るので、容量の大きさだけから原因確定とは言わない。

速度改修が主目的なら、見た目・動画形式・自動再生・ループなど維持する条件を先に決める。デザイン調整を表示維持とするのか、リニューアルまで含めるのかを確認する。SEO/AEOは別の検討枠として範囲を決める。

## 段階と完了条件

| 段階 | AIが行う作業 | 残すもの | 次へ進む条件 |
| --- | --- | --- | --- |
| 0 合意 | 相談内容を対象URL・操作・制約に変換 | 質問票、範囲表、権限表 | 操作してよい環境と禁止対象が明確 |
| 1 証拠保全 | 入力一覧、版、日時、SHA、除外を記録 | 受領物台帳、除外理由 | 秘密情報を複製せず基準版を固定 |
| 2 公開監査 | URL発見、HTTP、資産、HTML、依存関係の解析 | URL台帳、課題票 | 発見範囲と未確認範囲を説明可能 |
| 3 再現 | HTML再現→PHP実行→実DB等の順で段階化 | Docker構成、仮データ仕様 | 前後双方が同条件で動く |
| 4 最小改修 | 配信、URL、画像、初期化等を課題単位で変更 | 差分、対応課題ID、切戻し | 機能・画面の回帰なし |
| 5 比較 | 校正、予備試験、本試験、独立再集計 | 生記録、中央値、除外理由 | 条件・母数・ハッシュが一致 |
| 6 報告 | 原因・変更・数値・残課題・権限を整理 | 顧客報告、依頼一覧 | 推定と実測が混ざっていない |
| 7 適用 | 実環境の回帰、バックアップ、段階反映 | 本番適用記録、切戻し記録 | 実施権限と復旧経路がある |
| 8 保守 | 実施箇所の不具合・軽微調整を受付 | 保守台帳、終了時引継ぎ | 対象範囲・期限・追加費用を合意 |

この一覧は作業手順の例であり、特定案件の本番完了実績ではない。

## 初動でコピーするフォルダー

```text
project/
  context/           # 合意事項、担当、制約、引継ぎ
  inputs/            # 原本を保全。秘密ファイルは別の制限領域へ
  audit/             # URL・資産・コードの台帳
  lab/               # before / after / Docker / 仮データ
  tests/             # 操作・画像比較・測定の定義
  results/raw/       # 追記専用の測定セッション
  results/summary/   # 再生成できる集計
  reports/           # 顧客向けと内部向けを分離
  delivery/          # 明示した許可リストだけを梱包
```

名前に日時・版を付ける。「コピー 2」「コピー 3」で正本が分からなくなる運用を避ける。既存の重複を整理するときは、パス・内容SHA・Unicode正規化・片側だけのファイルを比較し、差分を保全してからアーカイブする。更新日時だけで最新を決めない。

## 母数の読み方

URL数、資産数、受領PHP数、指摘数、改修候補数、試験数は異なる集合である。台帳間で同じ課題を扱うこともあるため、件数を合算しない。CSVの行数は見出しを含むかを明記する。
