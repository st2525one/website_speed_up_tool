# 03 効く場所から直す

## 配信圧縮

gzipは内容を変えずに転送するバイト数を減らす。HTML・CSS・JS・JSON・XMLなどを対象に、実際に応答を返すnginx/Apache/CDNの担当者と設定する。応答のContent-EncodingとVaryを確認し、解凍後のSHAが元と一致することを検証する。MP4やJPEGを同じ考えで再圧縮しても、同等の効果は期待できない。

圧縮試算には元ファイルの版、圧縮方式・レベル、ツールの版を付ける。条件の違うサイズ値を混ぜず、実際のページ速度は別途計測する。圧縮だけではCSSの展開後サイズ、セレクター数、構文解析時間は減らない。

## キャッシュと版管理

問題例は次の資産参照である。アクセス時刻が変わるたび、同じ内容でも別URLになる。

```php
// 問題の形：アクセスごとに版が変わる
$version = $_SERVER['REQUEST_TIME'];
```

次の例はテーマ内の資産に限った一般形。資産がドキュメントルート側にある場合もあるため、実際の配置に合うURIとパスを使う。

```php
// ビルド／配備で更新する固定値。実行時刻は使わない。
$release = 'release-001';
wp_enqueue_style('site-style', get_theme_file_uri('/assets/css/style.css'), [], $release);
```

内容ハッシュはビルド時に作る。リリース番号＋mtime＋サイズを使う設計では、同サイズ・同mtimeの差替えを見落とすため、配備時のリリース更新を必須にする。巨大ファイルをアクセスごとに読み、ハッシュを計算する方法は採らない。

- 内容とURLが対応する版付き静的資産だけ、長いTTLやimmutableを検討する。
- 更新時・切戻し時も、新しい配備識別子で正しい内容を指す。古いURLの中身を差し替えてブラウザー任せにしない。
- HTML、ログイン応答、個人化ページ、フォーム、APIは別設計とする。静的資産向け設定を一括適用しない。
- `no-cache` は保存禁止ではなく再利用前の再検証。保存禁止は `no-store`。304は通信ゼロでも完全なキャッシュヒットでもない。
- gzipは配信段、TTLも配信段、REQUEST_TIMEはPHPの出力元。テーマエディターが見えても本番編集可能と決めず、公開権限と復旧手段を確認する。

## 画像・フォント・スクリプト

画面外・非表示の製品画像をlazyにし、実寸比を確かめてwidth/heightを指定する。ロゴや先頭スライドはeagerを検討する。すべての画像に同じ指定を付けない。縮小候補はJPEGはJPEG、PNGはPNGのまま比較し、画質・クリック領域・拡大表示への影響も確かめる。

```html
<!-- 例。数値は必ず対象画像の縦横比から決める -->
<img src="product.jpg" width="800" height="600" loading="lazy" alt="製品名">
```

画像容量の削減試算と、初期画面で読み込まなくなった効果を混ぜない。開閉後に必要な画像は依然取得される。`decoding="async"` などの属性を追加した際は、白抜け等の描画不良がないか確認する。問題が出たら指定を切り戻して比較し、ブラウザーの一般的な欠陥と断定せず、対象・版・再現条件を記録する。

フォントタグの重複は整理できるが、削除したタグ数と減った通信数は一致するとは限らない。書体やウェイトの削減は見た目を変える可能性があり、別の画面確認が要る。

DOMにしか依存しないタブ初期化は `load` 待ちからDOM準備時へ移せる。画像サイズ・canvas・スライダーに依存する初期化は残す。外部JSを一括deferにすると、直後のinline処理やキー入力イベントが未定義の関数を呼ぶことがある。WordPressで登録する場合は依存ハンドルと対象WP版を確認する。

## カタログ・ダウンロード・動画

カタログは冊子別にエンジン、XML/JSON、画像、PDF、版識別子を一覧化する。外側HTMLの版が固定でも、内部のbook.xml等に時刻パラメータが付く場合がある。生成ツール・ライセンス・次回再生成での上書きも確認する。ローカル用のisLocal周辺の互換修正を、そのまま本番最適化として渡さない。

ダウンロード画面はまずHTML圧縮。DOM要素が多いという事実だけでは、仮想化やページ分割を直ちに採用する根拠にはならない。CPUプロファイル、検索、アンカー、アクセシビリティ、業務上の一覧性を確認してから構造を変える。

動画ファイルを変更しない比較では、再圧縮候補の容量やSSIMを改善理由に数えない。元動画のmoovの位置を確認し、すでに先頭側にある場合はfaststartの付け直しを改善策に数えない。元の自動再生・ループ・muted・playsinline等を維持し、開始と全編再生を分けて検証する。

## 追加の公式資料

キャッシュの用語は [MDN HTTP Caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching)、WordPressの依存関係・実行戦略は [wp_enqueue_script](https://developer.wordpress.org/reference/functions/wp_enqueue_script/) を参照。対象環境と公式仕様を確認したうえで設定する。
