# 04 受領PHPを点検し、安全に実装する

## 全件台帳を先に作る

パス、役割、行数、SHA、実際のURL/テンプレート割当、共通include、課題ID、変更対象、実行確認、除外理由を記録する。ファイル数と実行されたテンプレート数は違う。使われていないように見えるコピーでも、テンプレート割当やリンクを確認せず削除しない。

受領総数、PHP数、検証できた数、追加ヘルパー、対象外を別々に数える。問い合わせ・機密設定は別扱いになることがある。対象外を含めて「全ファイルの実環境互換を確認した」と言わない。

## 性能候補の判断

| コードの形 | 改修候補 | 先に確認すること |
| --- | --- | --- |
| 同じ条件のget_postsを再実行 | 取得した配列を再利用 | 途中のフィルター・データ更新・post状態 |
| 存在確認のため全件を取得 | 1件のID取得等に絞る | 地域、廃番、公開状態の絞り込みを維持 |
| 項目ごとにtaxonomy/ACF検索 | クエリ・キャッシュ設計を見直す | 実DB、ACFフィールド、フック、クエリ計測 |
| 空の手順書ID配列を検索に渡す | 空ならクエリを発行しない | WP_Queryの空配列の意味、順序、件数 |
| 出力後もglobal postを変更したまま | 状態を戻す | テンプレート後半や関連表示の参照先 |
| メインクエリと二重に検索 | 重複を省く | pagination、プラグイン、検索仕様 |
| 全件ダウンロード一覧を構築 | まず圧縮、次に処理計測 | 全件表示が業務仕様かどうか |
| セッション保持中の外部照会・メール | タイムアウト、解放、非同期の候補 | 二重送信、配達保証、再試行、監査要件 |

性能候補は「コード上の可能性」である。仮データでクエリ回数を減らせても、本番の短縮ミリ秒を作らない。

## 対象PHP版の確認順

1. 実行イメージを正確なPHP版で固定し、`php -v` の実値を記録する。before/afterの実行系もそろえる。
2. 構文検査を全配布PHPに行う。
3. ACFがnull/falseを返す、配列が空、画像がURL/ID/配列で返る、termがWP_Error、投稿がない等の境界条件を試す。
4. E_ALLの警告・Deprecatedを失敗として捕捉する。`@`で消して合格にしない。
5. 以前成功していたケースのHTMLや挙動が変わっていないか比較する。エスケープの修正は入力と出力の両面で確認する。
6. WordPressの正しい呼出し順、実プラグイン、実DBに近いデータで統合試験する。
7. 回帰試験後に性能試験する。例外で処理を省略した結果だけ速くなるケースを除く。

短縮PHP開始タグを直すだけでは足りない。構文検査が全件合格でも、実行時の型・空値・依存関係で失敗し得る。境界条件を試し、以前成功していたケースの出力も維持する。仮データ検証の合格は、未受領プラグインや本番DBとの互換性を保証しない。

## パッケージの単位

ヘルパーを呼ぶテンプレートだけを納品すると未定義関数になる。functions.php・ヘルパー・利用側を依存単位としてまとめる。適用元SHAと変更後SHAを付け、別の改修済み版へ重ねて適用しない。サイト全体のZIPではなく、配布許可リストを基準にする。
