# 09 秘密情報と本番を守る

## 公開ファイルに秘密が含まれる場合

公開JavaScript等に認証情報を含む構造を見つけた場合は、値を出力せず、公開経路と連携所有者を確認する。読み込み元ページ数は参照範囲であり、被害件数や不正使用件数ではない。有効性・権限・利用履歴を調べていなければ未確認とする。

検出記録の共有時は、必要に応じてファイル名・行番号・日時も一般化する。匿名資料に実案件の検出経路や識別できる件数を残さない。

## 検出時の手順

1. 値を画面、ログ、プロンプト、スクリーンショット、ZIPに出さない。広い全文検索やターミナルへのcatを避ける。
2. 検出日時、場所、参照元ページ数、公開経路を値なしで記録する。
3. 連携所有者が先方かベンダーかを確認し、失効・再発行と利用履歴確認を依頼する。自分に権限がないアカウントを操作しない。
4. 新しい秘密値はサーバー側の制限された保管場所に置く。公開側へは表示用データだけをキャッシュして返す。
5. 旧値の無効化、公開ソース・キャッシュ・履歴・配布物に新値がないこと、表示の継続を確認する。単にJSから消しただけで完了にしない。
6. 必要な通知・契約上の扱いは先方の担当と決める。検出ドラフトの作成と送信を分ける。

## ラボで止めるもの

メール送信、購入・決済、本番管理画面、外部連携の実秘密、解析イベント、意図しない本番資産要求。フォームを止めたなら「フォーム送信は未検証」とする。before/after双方で同じ置換を行い、その省略が本番速度との差になることを報告する。

## 受領・ZIPの許可リスト

送ってよいファイルだけを選ぶ。`.env`、wp-config、DBダンプ、認証付きURL、トークン、private key、セッション、HARのヘッダーやCookieを混入させない。パスの除外だけでなく、配布ファイルの内容も値を表示せず検査する。正当なライセンスが必要なカタログエンジンやフォントを、汎用教材に丸ごと同梱しない。

共有する資料には、実案件の会社名・人名・対象ドメイン・ローカルパス・ソース識別子を残さない。実案件のファイル一覧・実測値・日付・ハッシュ等から特定できる場合もあるため、手順だけに一般化する。
