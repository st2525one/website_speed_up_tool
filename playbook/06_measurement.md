# 06 初回・再アクセスの速度を公平に測る

## 測定計画の例（実案件の条件ではない）

- 対象例：トップ、一覧、検索、ダウンロード、独立ビューアー。実際の利用者が待っている操作から選ぶ。
- 回線：4 Mbps・設定遅延150 ms、1 Mbps・設定遅延300 ms。4 Mbpsは500,000 bytes/s。これは回線エミュレーションであり、実際の4G端末・Wi-Fi・TCP全体の再現ではない。
- 各条件：変更前/後、初回/再アクセス、3回以上。予定アクセス数は対象数×回線数×2×2×反復数で算出する。
- 初回：新規ブラウザーコンテキスト。再アクセス：初回が成功した同一コンテキスト内の新規ページ。初回が失敗した場合、その再アクセスも比較母数から外す。
- 変更前/後の実行順を反復ごとに交互にし、同時実行しない。端末負荷・画面サイズ・CPU条件・ブラウザー版を固定する。
- 保存：生記録はセッションごとに追記保存。改修・観測コード・集計を版固定し、試験中のファイル変更を検出する。

## 指標を分ける

| 指標 | 何を見るか | 注意 |
| --- | --- | --- |
| TTFB/応答開始 | Navigation TimingのresponseStart等 | 起点と遅延の適用位置を校正する。本番TTFBや純PHP時間に外挿しない |
| DOMContentLoaded | DOM準備まで | 画像・動画完了ではない |
| load | loadイベントまで | 動画開始・操作可能・画面完成とは限らない |
| LCP | 観測中の最大コンテンツ描画 | 観測終了・タブ状態・ユーザー入力を記録。実ユーザーCWVではない |
| 動画開始 | 最初の再生フレーム等 | autoplay属性だけで成功にしない |
| 動画の動き | フレーム/再生時刻の進行 | 最初のフレーム表示と区別する |
| 表紙表示 | 対象画像のdecodeと表示状態、描画機会 | 画像200だけで合格にしない |
| 転送量 | HTML＋観測済みResource TimingのtransferSize | 途中の動画を含む全編の通信量ではない |
| CDP観測量 | CDPで観測した別系統のバイト数 | 上記に足さない。計上範囲が異なる |
| 本体サイズ | encodedBodySize / decodedBodySize | キャッシュ利用時も値を持ち、そのアクセスでの転送量ではない |
| キャッシュ数 | 同一オリジンのtransferSize=0等 | TAO不足の0、304、memory/diskを混同しない |

`ttfb_ms` の定義を記録する。ナビゲーション起点のresponseStartと、`responseStart - requestStart` は異なる。名称だけで別ツールのTTFBと比較しない。

## 遅延を校正してから本試験を始める

ブラウザーやエミュレーションの実装によって、設定遅延がTiming APIのどの区間へ記録されるかが変わる可能性がある。responseStartが短いことだけから、制限が無効と判断しない。responseStart以降の区間と全体時間も比較する。

校正では小さな固定応答を使い、0/150/300/1000/3000 ms、帯域制限なしで全体と各フェーズを比較する。次に帯域制限を加える。設定はナビゲーションより先に適用する。最小値を別条件と誤って組み合わせず、期待増分に上下限を設ける。校正と本試験のブラウザー版・経路をそろえる。

load・DCL・LCP・動画開始・表紙表示が設定遅延を含んでいるか、校正値と記録タイミングから確認する。校正時の実値と報告時の丸め値を区別し、他のブラウザー版へ結果を一般化しない。

## 観測をいつ終えるか

例えば、loadと必要コンテンツの準備の遅い方を待ち、さらに一定時間観測する。観測余白と1アクセスの上限時間は事前に決める。トップでは動画の開始・動き、カタログでは表紙を待つ。その他は定義した画面の準備を待つ。`networkidle`だけではループ動画や定期通信のある画面を適切に終えられない。

LCPは観測窓内の値。全編再生、ページをすべて送った後の転送量、長時間の停止・再開は別試験にする。

## 実行と集計の契約

```text
for profile, target, repeat:
    before/afterの順序を反復ごとに交替
    for variant:
        新しいcontextとpageを作る
        CDPで回線設定 → 初回goto → コンテンツ準備 → 観測 → 保存
        初回成功なら同じcontextで新pageを作り再アクセスを測る
        contextを閉じる
各条件・指標を独立に中央値集計し、n・除外理由・差分を併記
```

`browser_context.route()`等のルーティングを有効にするとHTTPキャッシュが無効になるため、キャッシュ比較に使わない。外部アクセス制限は別のネットワーク・配信制御で実現する。[Playwright公式](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-route)

`差分 = after - before`、`削減率 = (before - after) / before × 100`。基準0なら率を作らない。転送量と時間は別表にし、全資産一括の削減率を1ページの速度改善率に転用しない。中央値だけで異常を隠さず、生値、最小/最大、失敗を残す。n=3は小標本で、統計的有意差や本番の保証を意味しない。

## 無効とする例

対象画像の取得失敗、動画自動再生失敗、初回失敗後の再アクセス、途中でソース変更、旧観測版の混入、意図しない外部転送、背景タブによる観測不備。遅いから除外してはいけない。理由と件数を保存し、追加試験を元結果へ上書きしない。
